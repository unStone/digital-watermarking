# 数字水印实验室全站视觉改版设计

日期：2026-08-20

状态：已确认并进入实现；配图方向根据视觉复核调整为网页原生动画

参考方向：[有赞龙虾官网](https://claw.youzan.com/)

## 1. 背景与目标

当前站点已经具备 9 个可用的纯前端工具、完整的静态导航、FAQ 结构化数据、canonical、Open Graph、robots.txt 和 sitemap。问题不在功能数量，而在信息呈现仍像一组 Demo 的目录：访问者能找到工具，却不容易先理解数字水印的分类、原理和适用边界，也缺少统一而有辨识度的视觉语言。

本次改版的目标是把站点升级成一个“专业可信的数字水印实验室”：

1. 让用户在首屏理解本站能做什么，以及“文件不上传”的核心信任承诺。
2. 用准确的原理图解建立专业感，再把用户导向合适的工具。
3. 让首页与 9 个工具页共享同一套视觉系统和内容节奏。
4. 保留现有 URL、可抓取正文和 SEO 基础，不以视觉效果交换收录能力。
5. 保持纯静态、无构建、无后端的技术特征。

## 2. 设计原则

### 2.1 从参考站借鉴什么

借鉴有赞龙虾官网的页面节奏，而不是复制其品牌或销售内容：

- 强标题与大留白形成清晰的阅读停顿。
- 用章节编号、英文短标签和细分隔线建立编辑感。
- 卡片大小随信息重要性变化，避免所有入口机械等高。
- 大面积浅色页面中穿插少量深色区域，形成视觉锚点。
- 动效用于解释层级与信号流动，不作为持续装饰。

### 2.2 本站自己的设计命题

确定的视觉方向为“信号图谱”：从像素最低位、Unicode 码位、token 概率到 C2PA 签名链，把不可见信息呈现为可验证的信号。

确定的视觉策略为网页原生动态信号系统：

- CSS 与 SVG 共同承担品牌气氛、动态质感和原理表达。
- 动画只表现信号汇聚、概率偏置、空间变换和签名链流转，不使用泛化的 3D 科技素材。
- 关键内容保留为可抓取的 HTML 正文，动效不是正文的替代物。

## 3. 信息架构

### 3.1 全站共享外壳

每个页面共享以下结构：

1. 静态 HTML 顶部导航。
2. 章节化页面标题区。
3. 主要内容区。
4. 相关工具内部链接。
5. 全站工具导航与隐私承诺页脚。

JavaScript 仍只作为静态导航缺失时的兜底，不负责首屏正文或关键链接渲染。

### 3.2 首页结构

首页按“建立信任 → 讲懂问题 → 选择工具”的顺序组织：

1. **首屏主视觉**
   - 主标题表达“看不见的标记，也能看得懂”。
   - 明确覆盖检测、嵌入、验证与溯源。
   - 强调 9 个工具、纯前端处理、文件不上传。
   - 主行动进入 AI 文本检测，次行动进入 C2PA 内容凭证读取。
2. **水印工作流程**
   - 以“载荷 → 嵌入 → 传播 → 检测/验证”解释共同模型。
3. **四类原理图谱**
   - 文本：字符级隐写与统计式水印。
   - 像素：明水印、全屏无痕水印、LSB。
   - 频域：FFT 盲水印。
   - 内容凭证：EXIF 与 C2PA 来源链。
4. **9 个工具入口**
   - 按文本、图片与文件、鲁棒水印三个簇组织。
   - 主工具占据更大卡片，不做机械等高网格。
5. **方案对比**
   - 保留隐蔽性、鲁棒性、载体和典型场景等已有信息。
6. **本地处理承诺**
   - 解释为什么文件不上传，而不只显示一句口号。
7. **FAQ**
   - 保留现有高意图搜索问题和 FAQPage 结构化数据。

### 3.3 工具页结构

9 个工具页采用同一骨架，但核心工具操作保持在首屏附近：

1. 页面标题、适用场景和关键限制。
2. 核心操作区。
3. 与该工具对应的原理图解。
4. “能做 / 不能做”边界说明。
5. 相关工具入口。
6. 该主题的 FAQ 或注意事项。

工具算法、输入输出格式和现有交互逻辑不在本次改版中改变。

## 4. 视觉系统

### 4.1 色彩

- 基础浅色：冷白与极浅蓝灰，避免纯营销式暖白。
- 基础深色：深蓝黑，用于信号场和深色模式。
- 主信号色：钴蓝。
- 次信号色：青色。
- 红橙色仅表示风险、异常、破坏或重要警告，不作为常规装饰色。
- 现有成功、警告、危险语义颜色继续保留，但需统一对比度。

最终颜色值在实现阶段通过可访问性对比度检查后确定；视觉关系不得改变：钴蓝是主强调，青色是信号辅助，红橙色是异常语义。

### 4.2 字体与排版

- 不加载外部字体，继续使用系统中文无衬线字体栈。
- 标题使用更强的字号阶梯、紧凑字距和较短行长。
- 章节编号、英文标签、码位和技术数值使用等宽字体。
- 正文保持适合中文阅读的行高，不用小字号换取信息密度。
- 每页仅有一个 `h1`，标题层级与视觉层级一致。

### 4.3 网格、卡片与章节

- 页面最大内容宽度从当前 920px 扩展为适合编辑型落地页的宽容器，同时保留工具表单的舒适阅读宽度。
- 使用低对比度技术网格作为局部背景，不覆盖整页。
- 卡片采用细边框和轻量阴影，主卡片通过尺寸、内容和背景建立优先级。
- 深色信号场用于首屏主视觉或关键原理章节，不让全站持续处于高对比深色环境。
- 手机端改为自然单列，不使用水平滚动卡片墙。

### 4.4 主题

保留当前跟随系统的深浅色主题：

- 常规页面表面、文字和边框随系统切换。
- AI 主视觉所在的深色信号场在两种主题中保持一致，避免为同一张生成图维护两套风格。
- 所有图解和控件在深浅色下均需通过对比度与可辨识度检查。

### 4.5 动效

- 首屏可有一次性的信号线、粒子或扫描出现动画。
- 卡片仅使用轻微位移、边框与阴影反馈。
- 原理图的动效必须帮助理解“载荷如何移动或被检测”。
- 不使用持续循环的大面积动画。
- 完整支持 `prefers-reduced-motion: reduce`，关闭非必要运动。

## 5. 图像与图解资产

### 5.1 动态信号资产

实现 4 组同一视觉语言的网页原生动画：

1. **主视觉信号核心**：细线信号穿过验证核心，配合低密度频谱与状态节点。
2. **Token 概率场**：候选 token 经过选择场后形成有偏的统计波形。
3. **像素与频域场**：像素矩阵通过变换轴映射为频率同心场。
4. **C2PA 来源链**：签名数据包沿内容版本节点移动并到达验证状态。

共同风格约束：

- 使用细线、低透明度网格、钴蓝与青色信号，不使用厚重的蓝色 3D 科技材质。
- 运动幅度小、节奏慢，重点信号允许持续循环，其余元素只做呼吸反馈。
- 所有视觉由本地 HTML、CSS 与 SVG 构成，不依赖第三方图片或运行时脚本。
- 手机端重新排布核心位置，不用裁切桌面栅格图来适配。

### 5.2 精确图解

以下内容使用 SVG/CSS，而非生成图片：

- 载荷 → 嵌入 → 传播 → 检测流程。
- LSB 二进制最低位替换。
- 字符级隐写与统计式文本水印对比。
- FFT 频域嵌入示意。
- C2PA 清单与签名链结构。
- 各方案的隐蔽性、鲁棒性和适用场景对比。

图解必须提供可见标题、相邻正文或图注；必要时提供 `aria-label` 或 SVG 内的 `<title>` / `<desc>`。

### 5.3 加载与可访问性

- 动态视觉随 CSS 加载，不产生额外栅格图片请求，也不造成布局偏移。
- 装饰性动画使用 `aria-hidden="true"`；原理结论由相邻标题与正文完整说明。
- SVG 仅包含路径，不写入需要搜索引擎或读屏软件读取的关键信息。
- `prefers-reduced-motion: reduce` 下将动画缩短为单次静态呈现。

## 6. 技术实现边界

### 6.1 保持不变

- 纯静态 HTML/CSS/JavaScript。
- GitHub Pages 部署方式。
- 所有现有 URL。
- 9 个工具的算法与数据处理方式。
- 文件仅在浏览器本地处理的隐私模型。
- 现有搜索引擎验证文件与 IndexNow 密钥文件。

### 6.2 样式与代码组织

共享样式按职责拆分，避免单个大文件承载全部页面：

- `assets/theme.css`：颜色、排版、基础元素和主题变量。
- `assets/layout.css`：导航、容器、章节、卡片、页脚与响应式布局。
- `assets/signals.css`：信号网格、原理图解和动效。
- 页面已有的专用 CSS 只保留该工具独有的操作区样式。

共享 JavaScript 继续集中处理 toast、复制、下载和导航兜底。新增动效尽量由 CSS 完成，不建立客户端渲染框架。

单个手写源码文件以不超过约 500 行为目标；若职责仍然清晰，可有小幅偏差，但不把全站改版堆入一个文件。

### 6.3 浏览器与响应式

- 支持现代桌面与移动浏览器。
- 主要检查宽度为约 1440px、1024px、768px 和 390px。
- 工具操作区在手机端优先保证可用性，不为了保持桌面构图而缩小控件。
- 需要横向信息密度的表格保留局部滚动，不让页面整体横向溢出。

## 7. SEO 保留合同

视觉改版不得破坏以下条件：

1. 页面 URL 与 canonical 不变。
2. 现有页面的 title、description、Open Graph 和 Twitter 元信息默认逐字保留；若实现阶段发现需要优化，必须先提供搜索意图依据并单独确认，不能随视觉改版顺手改写。
3. 首页 FAQPage、WebSite 和 SoftwareApplication JSON-LD 保持可解析，并与页面可见内容一致。
4. 关键导航和正文存在于初始 HTML，不依赖 JavaScript 注入。
5. 每页一个明确 `h1`，`h2` / `h3` 顺序合理。
6. 9 个工具在首页与页脚保持可抓取的内部链接。
7. 原理图配有可抓取文字说明，图片中的视觉信息不会成为唯一信息源。
8. robots.txt、sitemap.xml、Google Search Console 验证文件和 IndexNow 文件不删除。
9. sitemap 只在页面内容完成后更新 `lastmod`，不改变路径集合。
10. 改版前后对每页的 SEO 元信息、标题层级、内部链接和 JSON-LD 做自动对比。

## 8. 可访问性与隐私

- 所有表单保持显式 label。
- 键盘可操作所有按钮、链接、文件上传和折叠内容。
- 焦点状态清晰可见，不只依赖颜色表达状态。
- 正文和控件满足 WCAG AA 级常用对比度要求。
- 动效遵循用户的减少动态效果设置。
- 不引入用户追踪、第三方图片托管或需要上传文件的服务。
- 不引入第三方视觉运行时或远程素材请求。

## 9. 验收标准

### 9.1 视觉与响应式

- 首页和 9 个工具页呈现统一的“信号图谱”视觉语言。
- 深浅色主题均无不可读文本、透明图片冲突或错误语义色。
- 390px 宽度下无页面级横向滚动，核心工具无需缩放即可操作。
- 首屏、原理区、工具入口和 FAQ 的层级清晰。

### 9.2 功能回归

- 9 个工具的主要输入、处理、复制、下载和清理流程与改版前一致。
- 所有内部链接与静态资源返回成功。
- JavaScript 控制台无新增错误。
- 文件仍只在浏览器本地处理。

### 9.3 SEO 与语义

- 每页 canonical、description、robots、Open Graph 和 Twitter 元数据存在。
- JSON-LD 可解析且与可见内容一致。
- 首页和页脚都能在禁用 JavaScript 时提供完整工具导航。
- 原有 sitemap 路径全部保留。
- 图片均具有正确的尺寸、加载策略和替代文本。

### 9.4 性能

- 不引入前端框架或常驻第三方脚本。
- 首屏图片不会造成明显布局偏移。
- 生成图片经过压缩，不以超大原图直接发布。
- 动效不持续占用大量 CPU/GPU，并能在减少动态效果模式下关闭。

## 10. 非目标

本次改版不包含：

- 修改水印算法或新增工具。
- 引入账号、后端、数据库或文件上传。
- 更改域名或 URL 结构。
- 重写现有技术结论和行业事实。
- 复制有赞龙虾的品牌图形、文案、吉祥物或具体页面素材。
- 以动画或图片替代可抓取正文。

## 11. 实施顺序建议

1. 建立共享视觉变量与布局组件。
2. 生成并压缩 4 张 AI 视觉资产。
3. 改造首页并完成 SEO 对照检查。
4. 制作共享原理图解组件。
5. 按文本工具、内容凭证、图片工具、频域工具的顺序迁移 9 个工具页。
6. 做全站功能、响应式、深浅色、可访问性和 SEO 回归。

实施计划将在本设计文档通过用户审阅后另行编写。
